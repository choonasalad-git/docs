Building a custom screen involves writing a C# graph that manages your data, designing an XML-based ASPX layout that presents it, and registering the whole thing in your Customization Project so it can be published to the ERP. This guide walks you through each step in order, from an empty project to a working, navigable screen.

<Note>
  Before you start, make sure you have an active Customization Project open in the ERP's Customization editor. All artifacts — the graph, the screen definition, and the sitemap node — must live in the same project so they are published and versioned together.
</Note>

## Step-by-step guide

<Steps>
  <Step title="Create the PXGraph for the screen">
    Every custom screen is backed by a **PXGraph** — the C# class that owns the data views, actions, and business logic. Create a new code file in your Customization Project and define your graph.

    A minimal graph for a single-entity maintenance screen looks like this:

    ```csharp
    using PX.Data;

    public class MyScreenGraph : PXGraph<MyScreenGraph, MyRecord>
    {
        // Primary data view — drives the current record shown in the form
        public PXSelect<MyRecord> Records;

        // Standard toolbar actions wired up automatically by the framework
        public PXSave<MyRecord> Save;
        public PXCancel<MyRecord> Cancel;
    }
    ```

    Key points about this graph:
    - `PXGraph<TGraph, TPrimary>` — the second type parameter tells the framework which DAC is the "primary" record for the screen's navigation keys.
    - `PXSelect<MyRecord>` — declares a data view that returns all rows of `MyRecord`. You can restrict this with a `Where` clause when needed.
    - `PXSave` and `PXCancel` — these two action declarations are enough for the framework to render the standard Save and Cancel toolbar buttons automatically.

    If your screen needs a detail grid (a master/detail layout), add a second data view filtered by the primary record's key:

    ```csharp
    public PXSelect<
        MyDetailRecord,
        Where<MyDetailRecord.parentID, Equal<Current<MyRecord.recordID>>>
    > Details;
    ```

  </Step>

  <Step title="Define the Screen ID">
    Every custom screen requires a unique **Screen ID**: an 8-character code made up of your company's 2-character prefix followed by 6 digits.

    ```
    Format:   XX 000000
              ↑↑ ↑↑↑↑↑↑
              │└ 6-digit number (000001 – 999999)
              └─ 2-letter company prefix (assigned to your organisation)
    ```

    Examples of valid Screen IDs: `AC000001`, `XX100050`, `ZZ990010`.

    <Note>
      Screen IDs must be unique across the entire ERP installation. Before you assign a number, check the **Screens** list in your Customization Project and search the sitemap to confirm the ID is not already in use. Duplicate IDs will cause a publish conflict that is difficult to resolve after deployment.
    </Note>

    The Screen ID becomes:
    - The filename of your ASPX file (e.g., `AC000001.aspx`)
    - The URL path to the screen (e.g., `/Pages/AC/AC000001.aspx`)
    - The identifier used in access rights, audit logs, and deep-link URLs
  </Step>

  <Step title="Use the Screen Editor to create the ASPX screen definition">
    Open the **Screen Editor** inside the ERP's Customization interface. The Screen Editor provides a visual designer where you drag controls onto a canvas and configure their properties through a property panel — without writing raw XML by hand.

    To create a new screen definition:

    1. In your Customization Project, navigate to **Screens** and click **Add Screen**.
    2. Enter the Screen ID you defined in the previous step.
    3. Select **Create New Screen** and choose your graph class (`MyScreenGraph`) from the dropdown.
    4. Click **Create** — the editor scaffolds a minimal ASPX file with a `PXDataSource` already bound to your graph.

    The Screen Editor saves your layout as an XML document inside the Customization Project. You can switch to the **Source** tab at any time to view or edit the raw XML directly.
  </Step>

  <Step title="Configure the PXFormView and primary data view">
    With the new screen open in the Screen Editor, add a **PXFormView** control to the canvas. This is the primary container for a single-record form layout.

    Set the following properties on the `PXFormView`:

    | Property | Value |
    |---|---|
    | `ID` | `form` (convention) |
    | `DataMember` | The name of your graph's primary data view — e.g., `Records` |
    | `DataSourceID` | `ds` (the auto-generated PXDataSource control ID) |

    The equivalent raw XML for a configured `PXFormView` looks like this:

    ```xml
    <px:PXFormView ID="form" runat="server"
        DataSourceID="ds"
        DataMember="Records"
        Width="100%"
        Caption="My Record">
      <Template>
        <px:PXLayoutRule runat="server" StartRow="True" />
        <px:PXTextEdit ID="edRecordCD" runat="server"
            DataField="RecordCD" />
        <px:PXTextEdit ID="edDescription" runat="server"
            DataField="Description" />
        <px:PXDateTimeEdit ID="edCreatedDate" runat="server"
            DataField="CreatedDate" />
      </Template>
    </px:PXFormView>
    ```

    Add controls inside the `<Template>` block. Each control's `DataField` attribute matches the property name on your DAC. Use `PXLayoutRule` elements to control the number of columns and where new rows begin.
  </Step>

  <Step title="Add the screen to the Customization Project">
    Confirm that both the graph code file and the ASPX screen definition are listed under the correct sections of your Customization Project:

    - **Code** section → `MyScreenGraph.cs`
    - **Screens** section → `AC000001` (your Screen ID)

    If either artifact is missing, use the **Add** button in the relevant section to include it. The project must contain both before you publish, otherwise the screen will either have no logic (missing graph) or no UI (missing screen definition).

    This is also the point at which you add the **Sitemap** node that places the screen in the ERP menu. See the [Navigation & Menus](/screens/navigation-and-menus) guide for full details on that step.
  </Step>

  <Step title="Publish and navigate to the screen">
    With the Customization Project complete, click **Publish** (or **Publish All** if you want to push the entire project). The platform compiles the C# code, deploys the ASPX file, and registers the sitemap node.

    After publishing:
    - Navigate directly to your screen using its URL: `/Pages/AC/AC000001.aspx`
    - Or find it in the ERP menu under the module and menu path you configured in the sitemap

    If the screen does not appear in the menu, verify that:
    1. The sitemap node was saved inside the project before publishing.
    2. Your user account has been granted access to the screen via **Access Rights**.
    3. The Customization Project published without errors (check the publish log for compilation failures).

    <Tip>
      Use the ERP's **Search** bar and type your Screen ID (`AC000001`) to jump directly to the screen without navigating the menu tree. This is useful during development when the sitemap entry may not yet be in its final location.
    </Tip>
  </Step>
</Steps>

## Full screen XML example

The following snippet shows a complete, minimal screen definition for a single-entity maintenance screen with a toolbar, a form, and a detail grid:

```xml
<%@ Page Language="C#" MasterPageFile="~/MasterPages/FormDetail.master"
    AutoEventWireup="true" ValidateRequest="false"
    CodeFile="AC000001.aspx.cs" Inherits="Page_AC000001"
    Title="My Custom Screen" %>

<%@ MasterType VirtualPath="~/MasterPages/FormDetail.master" %>

<asp:Content ID="cont1" ContentPlaceHolderID="phDS" runat="server">
  <px:PXDataSource ID="ds" runat="server" Visible="True" Width="100%"
      TypeName="MyScreenGraph"
      PrimaryView="Records">
    <CallbackCommands>
      <px:PXCallbackCommand Name="Save" />
      <px:PXCallbackCommand Name="Cancel" />
    </CallbackCommands>
  </px:PXDataSource>
</asp:Content>

<asp:Content ID="cont2" ContentPlaceHolderID="phF" runat="server">
  <px:PXFormView ID="form" runat="server"
      DataSourceID="ds"
      DataMember="Records"
      Width="100%"
      Caption="My Record">
    <Template>
      <px:PXLayoutRule runat="server" StartRow="True" ControlSize="M" LabelsWidth="S" />
      <px:PXTextEdit ID="edRecordCD" runat="server" DataField="RecordCD" />
      <px:PXTextEdit ID="edDescription" runat="server" DataField="Description" />
      <px:PXLayoutRule runat="server" StartRow="True" />
      <px:PXDateTimeEdit ID="edCreatedDate" runat="server" DataField="CreatedDate" />
      <px:PXCheckBox ID="chkIsActive" runat="server" DataField="IsActive" />
    </Template>
  </px:PXFormView>
</asp:Content>

<asp:Content ID="cont3" ContentPlaceHolderID="phG" runat="server">
  <px:PXGrid ID="grid" runat="server"
      DataSourceID="ds"
      DataMember="Details"
      Width="100%"
      SkinID="Details">
    <Levels>
      <px:PXGridLevel DataMember="Details">
        <Columns>
          <px:PXGridColumn DataField="LineNbr" Width="60px" />
          <px:PXGridColumn DataField="DetailDescription" Width="300px" />
          <px:PXGridColumn DataField="Qty" Width="80px" />
        </Columns>
      </px:PXGridLevel>
    </Levels>
    <AutoSize Container="Window" Enabled="True" MinHeight="150" />
  </px:PXGrid>
</asp:Content>
```

<Warning>
  Always set `TypeName` on `PXDataSource` to the fully qualified class name of your graph. If your graph is inside a namespace, include it: `TypeName="MyCompany.MyModule.MyScreenGraph"`. A mismatched `TypeName` causes a runtime error when the screen loads.
</Warning>
