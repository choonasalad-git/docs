Welcome to the Customization Platform documentation. Whether you're extending an existing ERP screen, creating brand-new data tables, or wiring up complex business logic, this platform gives you a structured, type-safe environment to build production-grade customizations in C#/.NET — all without touching the ERP application's core source code. Use these docs to go from your first project setup to deploying fully packaged customizations to production.

## How Customization Works

The four steps below describe the end-to-end workflow you'll follow for virtually every customization project, from a simple field addition to a fully featured new module.

<Steps>
  <Step title="Set Up Your Environment">
    Install Visual Studio (or VS Code), reference the `PX.Data` and `PX.Objects` NuGet packages, and verify that your development machine can connect to a running ERP instance. A correctly configured environment means faster iteration and reliable deployments.
  </Step>
  <Step title="Create a Customization Project">
    Open the ERP application's **Customization Projects** screen and create a new project. The project acts as a container for every artifact you build — DACs, graphs, screens, and scripts — and tracks which version of each artifact is deployed to each environment.
  </Step>
  <Step title="Build Custom Tables and Screens">
    Define Data Access Classes (DACs) to model any new database tables you need, annotating fields with attributes such as `PXDBString`, `PXDBInt`, and `PXDBDecimal` to control database mapping and UI behavior. Query your DACs with `PXSelect` and Business Query Language (BQL) inside a `PXGraph`. Build out the user interface by adding new screens or extending existing ones via `PXGraphExtension` or `PXCacheExtension`. Add event handlers — `RowSelected`, `RowInserted`, `RowUpdated`, and `RowDeleted` — to enforce business rules at the right moment in the data lifecycle.
  </Step>
  <Step title="Deploy and Publish">
    Compile your project, add the output assembly to your Customization Project, and click **Publish**. The platform validates the package, applies any database schema changes, and makes your customization live — with a full rollback available if anything goes wrong.
  </Step>

</Steps>
