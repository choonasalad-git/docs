## Unbound field

Create an unbound decimal / integer field with the following identifier:

```csharp UsrVendorMOQ.cs
#region UsrVendorMOQ
public abstract class usrVendorMOQ
    : BqlDecimal.Field<usrVendorMOQ>
{
}

[PXDecimal(6)]
[PXUIField(DisplayName = "Minimum Order Qty", Enabled = false)]
public decimal? UsrVendorMOQ { get; set; }
#endregion
```

The field is added to the relevant PO and SO order-line DAC extensions and exposed on the corresponding order entry grids.

```csharp SOLineExt.cs
using System;
using PX.Data;
using PX.Data.BQL;
using PX.Objects.PO;
using PX.Objects.SO;

namespace SalesOrdersWorkspace
{
    public sealed class SOLineExt : PXCacheExtension<SOLine>
    {
        public static bool IsActive() => true;

        #region Unbound Fields
        // Field goes here before or after other blocks
        #endregion
    }
}
```

The field does not need to be persisted to the database because it represents reference information derived from the existing Vendor MOQ configuration.

## FieldSelecting event

Implement an event handler for the unbound field using the applicable `FieldSelecting` event.

The event handler will:

- Identify the Inventory ID for the current order line.
- Identify the applicable Vendor ID where required.
- Retrieve the current Vendor MOQ from the appropriate inventory / vendor record.
- Assign the retrieved value to the unbound `UsrVendorMOQ` field for display.
- Return blank / null when no applicable MOQ exists.

Conceptually:

```text
Order Line → Inventory ID + Vendor Context → Vendor Inventory Record → MOQ → UsrVendorMOQ (unbound)
```

```csharp FieldSelecting.cs
#region FieldSelecting
protected virtual void _(
    Events.FieldSelecting<SOLine, SOLineExt.usrVendorMOQ> e
)
{
    if (e.Row?.InventoryID == null)
        return;

    POVendorInventory vendorInventory = SelectFrom<POVendorInventory>
        .Where<
            POVendorInventory.inventoryID
                .IsEqual<@P.AsInt>
            .And<POVendorInventory.subItemID
                .IsEqual<@P.AsInt>>>
        .View
        .Select(
            Base,
            e.Row.InventoryID,
            e.Row.SubItemID
        )
        .TopFirst;

    e.ReturnValue = vendorInventory?.MinOrdQty;
}
#endregion
```

## Data retrieval

The implementation must use the existing MOQ source of truth rather than duplicating MOQ data.

The lookup should use the appropriate inventory / vendor relationship and, where applicable, consider:

- Inventory ID
- Vendor ID
- Vendor Location
- Purchase Unit / UOM
- Active / default vendor configuration

The exact lookup criteria should match the existing business rules used by the Stock Item screen to determine Vendor MOQ.

## Performance

Because `FieldSelecting` may execute frequently while grids are rendered or refreshed, the implementation should minimize unnecessary database queries.

Where possible:

- Use existing graph / cache records before querying the database.
- Use parameterised / select queries against indexed fields.
- Avoid repeated retrieval of the same Inventory / Vendor combination during a single screen operation.
