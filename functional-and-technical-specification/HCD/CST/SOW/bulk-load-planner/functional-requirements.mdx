description: "Functional requirements for Sales Order Bulk Load Visibility: stock item packaging, line and order calculations, and the Calculate Load action."
---

<Steps>
  <Step title="Stock Item packaging configuration">
    Add the following custom fields to the Inventory Item / Stock Item:

    - `UsrUnitsPerCarton` — Number of individual units contained within one carton.
    - `UsrCartonsPerPallet` — Number of cartons contained on one full pallet.
    - `UsrUnitsPerPallet` — Number of individual units contained on one full pallet.

    These fields are user-maintainable and represent the standard bulk packaging configuration for the stock item.

    It is appropriate that `UsrUnitsPerPallet` automatically derives from:

    ```text
    UsrUnitsPerCarton × UsrCartonsPerPallet
    ```

    Alternatively, it may remain independently maintained where actual pallet configuration does not always represent a direct multiplication of the carton configuration. Future carrier or freight profiles are a real use case.
  </Step>
  <Step title="SO line visibility">
    Add unbound fields to the `SOLine` extension to expose the relevant bulk / load information during Sales Order entry.

    The Sales Order grid should display enough information for the user to understand the physical impact of each line, including:

    - Units per Carton
    - Cartons per Pallet
    - Units per Pallet
    - Calculated Cartons
    - Calculated Pallets

    These fields are informational and must not modify the packaging configuration held against the Stock Item.
  </Step>
  <Step title="Line-level calculation">
    When an Inventory Item and Order Quantity are present, the system calculates the estimated carton and pallet requirements for the line.

    Conceptually:

    ```text
    OrderQuantity ÷ UsrUnitsPerCarton = Carton requirement
    OrderQuantity ÷ UsrUnitsPerPallet = Pallet requirement
    ```

    Calculations should retain sufficient decimal precision to indicate partial cartons or pallets where applicable.

    Example: an order quantity of 1,200 units for an item configured as 20 units per carton and 1,000 units per pallet would represent:

    - 60 cartons
    - 1.2 pallet equivalents

    This provides users with immediate visibility of the approximate load generated by each Sales Order line.
  </Step>
  <Step title="Packaging data retrieval">
    When a Stock Item is selected, the system retrieves the corresponding packaging values from the Inventory Item record and exposes them through the unbound `SOLine` fields.

    If the Inventory Item is changed, the displayed values and calculated load information must refresh accordingly.

    Where packaging information has not been configured, the applicable fields should remain blank or zero in accordance with the agreed UI standard, and must not prevent order entry.
  </Step>
  <Step title="Shipping tab load summary">
    Add a **Load Summary** panel to the Sales Order Shipping tab.

    The panel contains order-level unbound fields representing the consolidated load, including at minimum:

    - Total Units
    - Total Cartons
    - Total Pallet Equivalents

    Additional values such as full pallets, partial pallets, weight, or volume may be added in future enhancements if the required source data is available.
  </Step>
  <Step title="Calculate Load button">
    Add a **Calculate Load** action / button to the Load Summary panel.

    Order-level load calculations are only performed when the user presses this button. When selected, the system will:

    1. Read all applicable Sales Order lines.
    2. Retrieve the bulk configuration associated with each Inventory Item.
    3. Calculate the carton and pallet requirements for each line.
    4. Aggregate the calculated values.
    5. Populate the unbound order-level Load Summary fields.

    This approach avoids repeatedly performing aggregate calculations whenever the Sales Order is refreshed or individual fields are changed.
  </Step>
  <Step title="Recalculation behavior">
    The Load Summary represents the Sales Order at the point the **Calculate Load** action was last executed.

    If order quantities, inventory items, or lines are subsequently changed, the user must press **Calculate Load** again to refresh the totals.

    The button-driven calculation should therefore be clearly understood as an on-demand estimate rather than a continuously maintained transaction total.
  </Step>
</Steps>
